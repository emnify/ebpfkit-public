# ebpftest

The `ebpftest` package contains golang utilities and helpers that simplify the testing of eBPF programs from golang userpace.

This package contains:
- `Mock` that brings mocking functionality to eBPF
- helpers to be used in tests, such as `RequireVariableEqual` and `RequireNoError`


## Effortlessly mocking eBPF programs

This package allows golang tests to replace a eBPF program or sub-program (eBPF function) on-demand with a stub, without having to modify eBPF code.
In addition, the user can:
- assert that the mock has been called 
- assert input arguments
- specify the return value of the mock


### Usage

The following example will replace eBPF functions `foo` and `bar` with mocks. 
```golang
func Test(t *testing.T) {

    type FunctionsToMock struct {
        Foo func()         `ebpf:"foo"`
        Bar func(any, any) `ebpf:"bar"`
    }

    collectionSpec = <specs of the eBPF programs provided by Cilium/ebpf>
    mock = ebpftest.NewMock[FunctionsToMock](t, collectionSpec)
}
```

One can then set the expectation that a mock gets called:
```golang
mock.Expect().Foo()
```

One can also set expectations on all (or some) of the input arguments
```golang
mock.Expect().Bar(uint32(42), ebpftest.Any)
```

Mocks return 0 by default. One can set a different return value by declaring a function with `ebpftest.Res[T]` result:
```golang
type FunctionsToMock struct {
    Foo func() ebpftest.Res[uint32] `ebpf:"foo"`
}

mock.Expect().Foo().Return(42)
```

### Example

Here is a full example, showcasing both the eBPF part and the golang part.
```C
// test.c
#include <bpf/bpf_helpers.h>

__noinline int foo(void)
{
    int res = 42;
    barrier_var(res);
    return res;
}

struct custom_struct {
    int member;
};

__noinline static int bar(int param1, struct custom_struct *param2)
{
    barrier_var(param1);
    barrier_var(param2);
    return param1 + param2.member;
}

SEC("tc")
int test(void *ctx)
{
    int x = foo();
    barrier_var(x);
    struct custom_struct y = {.member = 24};
    return bar(x, &y);
}
```
After generating the golang bindings, e.g. with
```
go run github.com/cilium/ebpf/cmd/bpf2go t test.c 
```
the userspace can mock `foo` and `bar` and set expectations that the mocks get called.
```golang
type customStruct struct {
	Member uint32
}

type mockedFuncs struct {
	Foo func() Res[uint32] `ebpf:"foo"`
	Bar func(uint32, *customStruct) `ebpf:"bar"`
}

func TestMock(t *testing.T) {
	spec, err := loadT() // loads specs generated by ebpf2go

	mock := NewMock[mockedFuncs](t, spec)

	var prog struct {
		*ebpf.Program `ebpf:"test"`
	}
	ebpftest.RequireNoError(t, spec.LoadAndAssign(&prog, nil))
	defer prog.Close()

	// Registed expectations
	mock.Expect().Foo()
	mock.Expect().Bar(0, &foo{Member: 24})

    /* Run the program
        Note 1: the kernel expects at least 14 bytes input for XDP and SKB programs.
        Note 2: one can also use prog.Run
    */
    _,_,_ = prog.Test(make([]byte, 14)) 

    // Register new expectations. This time, the Foo mock returns a custom value.
	mock.Reset()
	mock.Expect().Foo().Return(1)
	mock.Expect().Bar(1, &foo{Member: 24})
    _,_,_ = prog.Test(make([]byte, 14)) 
}
```

If they user is not interested in setting expectations on mock arguments, one can define mocks and set expectations as following:
```golang
type FunctionsToMock struct {
        Bar func(any, any) `ebpf:"bar"`
}
mock.Expect().Bar(ebpftest.Any, ebpftest.Any)
```

### Limitations
- can't mock inlined functions.
- mocked calls are evaluated once. If the user wants to setup another expectation on a mock `m`, they can call `m.Reset()`, followed by a new `m.Expect()`
- mocks are simple stubs, can't have custom eBPF code as part of the mock (i.e. no equivalent of `.Do` like in `gomock`).
